# iLlama v3.2.0

iLlama 3.2.0 is a stability-focused runtime refactor and launch-workbench
redesign. Once every external gate succeeds, the formal download is a signed and notarized macOS Apple Silicon DMG. Windows remains a source-level build,
test, and preview target and has no 3.2.0 Release asset.

## Highlights

- The backend runtime snapshot is the single source of truth for actual model,
  port, PID, uptime, detected model ID, and server capabilities.
- Editing launch settings while a model runs affects only the next launch;
  connection and test views continue to show the active service.
- Settings schema v3 preserves launch, sampling, tray, directory, and log-layout
  preferences with serialized atomic patches and corrupt-file recovery.
- `llama-server` capability probing and command preview share the same command
  specification; unsupported optional flags are omitted.
- GGUF scanning distinguishes ready, limited, and invalid files. Invalid models
  cannot launch, while limited metadata is surfaced as a warning.
- The launch workbench presents the actual runtime at the top, groups advanced
  controls, and uses a resizable persistent bottom log dock.
- Connection checks and smoke tests use the model ID returned by `/v1/models`,
  with explicit timeouts and cancellable chat requests.
- Keyboard, focus, screen-reader semantics, narrow-window layout, dark mode, and
  reduced-motion coverage have been expanded.

## Runtime requirements

iLlama does not bundle or download `llama-server`. Install a compatible external
binary or choose one in the app, then select a local GGUF. Optional command flags
are enabled only when the selected server reports support.

## Conditional release assurance

No release-ready claim is made by this document alone. The `v3.2.0-rc.1`
prerelease and `v3.2.0` final release may be created only by the protected manual
workflow after its GitHub configuration, credentials, candidate tag/SHA, exact
required checks, and run-bound evidence all pass. Each CI and acceptance run
must report the selected tag in GitHub's `head_branch`; a `main` push run for
the same SHA cannot be reused for publication.

The release gate requires:

- packaged native Tauri WebView/IPC acceptance with a real external
  `llama-server` and GGUF, including health downgrade/recovery, models,
  non-stream and SSE chat, cancellation, structured recovery, and stop;
- executable `curl` acceptance recording the exact binary path, SHA-256,
  `curl --version`, endpoint, detected model ID, and transcript hash; GUI client
  profiles remain Pending configuration references;
- fresh RustSec JSON with zero vulnerabilities and an exact match to the 17
  time-bounded informational warning reviews in
  `docs/security/rustsec-3.2.0.md`;
- Developer ID signing, hardened runtime, notarization, stapling, Gatekeeper,
  and a portable `<SHA256><two spaces><basename>` checksum;
- final-only acceptance of the exact signed RC artifact on an ephemeral clean
  GitHub-hosted `macos-15` arm64 runner, mounted read-only and launched through
  LaunchServices.

The clean runner is evidence for that ephemeral macOS 15 environment, not every
physical Mac, older macOS release, MDM configuration, or upgraded user profile.
An unsigned/ad-hoc diagnostic may confirm both Info.plist and Mach-O deployment
targets are macOS 11.0, but it is not signing, notarization, or release evidence.

## External blockers

Publication remains blocked until the protected `macos-release` environment,
its sole self-approving maintainer reviewer, exact tag policies, branch
protection/check names, six Apple
credential values, the separate least-privilege infrastructure-audit token, two
real-model acceptance inputs, candidate tags, successful `push` CI runs, and
their exact `workflow_dispatch` artifacts exist on GitHub; the tagged commit
must also belong to protected `main`. The repository audit
reports these as external state and never creates secrets, tags, releases, or
runs.

Unsigned diagnostic artifacts are never attached to a Release. The signed
release contains only `iLlama_3.2.0_aarch64.dmg` and its `.dmg.sha256`; it
contains no Windows installer or archive.

See `docs/client-compatibility.md`, `docs/release-strategy.md`, and
`docs/release-checklist.md` for the evidence contract and operator gates.
