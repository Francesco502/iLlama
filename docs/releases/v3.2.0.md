# iLlama v3.2.0

iLlama 3.2.0 is a stability-focused runtime refactor and launch-workbench
redesign. The formal download is a signed and notarized macOS Apple Silicon DMG.
Windows remains available for source-level build, test, and preview validation,
but is not shipped as a 3.2.0 Release asset.

## Highlights

- The backend runtime snapshot is the single source of truth for actual model,
  port, PID, uptime, detected model ID, and server capabilities.
- Editing launch settings while a model runs now affects only the next launch;
  connection and test views continue to show the active service.
- Settings schema v3 preserves launch, sampling, tray, directory, and log-layout
  preferences with serialized atomic patches and corrupt-file recovery.
- `llama-server` capability probing and command preview share the same command
  specification; unsupported optional flags are omitted.
- GGUF scanning distinguishes ready, limited, and invalid files. Invalid models
  cannot launch, while limited metadata is surfaced as a warning.
- The launch workbench presents the actual runtime at the top, groups advanced
  controls, and uses a resizable persistent bottom log dock.
- Connection checks and smoke tests use the model ID returned by `/v1/models`,
  with explicit timeouts and cancellable chat requests.
- Keyboard, focus, screen-reader semantics, narrow-window layout, dark mode, and
  reduced-motion coverage have been expanded.

## Runtime requirements

iLlama does not bundle or download `llama-server`. Install a compatible external
binary or choose one in the app, then select a local GGUF. Optional command flags
are enabled only when the selected server reports support.

## Release assurance

The `v3.2.0-rc.1` prerelease and `v3.2.0` final release are created only by the
manual protected workflow. The published DMG must pass Developer ID signing,
Apple notarization, staple validation, Gatekeeper assessment, and SHA-256
verification. Missing credentials or a failed check blocks publication; unsigned
diagnostic artifacts are never attached to a Release.

The release gate also requires:

- frontend, Playwright/a11y, Rust, npm audit, and RustSec checks;
- a real external-server matrix covering GGUF scan → start → health → models →
  chat → stop;
- at least one external client with its exact tested version recorded;
- a clean Apple Silicon Mac acceptance run before the final release.

See `docs/client-compatibility.md` and `docs/release-checklist.md` for the recorded
matrix and operator evidence.
