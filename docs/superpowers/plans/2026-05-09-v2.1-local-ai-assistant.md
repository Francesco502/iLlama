# iLlama v2.1 Local AI Assistant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make iLlama feel closer to a local Gemini/ChatGPT-style assistant by adding assistant modes, long-form writing helpers, conversation analysis, and automatic long-context compression.

**Architecture:** Extend the existing v2 chat workspace instead of creating a separate product surface. React owns assistant modes, writing actions, compression orchestration, memory display, and conversation analysis UI; `llama-server` remains the only generation backend through OpenAI-compatible endpoints; Rust continues to store chat JSON opaquely and only extracts summary fields for the history index. Long conversations are compressed into local conversation memory before requests are sent, preserving recent turns verbatim and inserting a generated summary as a system-context message.

**Tech Stack:** Tauri v2, Rust stable, React 18, TypeScript, Vite, Vitest, Testing Library, Cargo tests, `llama-server`, OpenAI-compatible `/v1/chat/completions`, existing local JSON chat history, existing Markdown renderer, existing context budget heuristic.

---

## Product Target

v2.1 should make the app useful for real daily work, not only chat demos. The target user can:

1. Choose a task mode such as normal chat, novel writing, long-content analysis, coding, or translation.
2. Keep long conversations going without silently dropping important earlier context.
3. Ask the app to analyze the current conversation and produce summaries, decisions, timelines, characters, or next actions.
4. Use writing actions for novels: brainstorm, outline, character bible, chapter draft, expand, rewrite, continue, and consistency check.
5. See what the app remembered after compression, and manually refresh or clear that memory.
6. Keep all generated summaries and memories local, stored with the conversation.

## Scope

### Included In v2.1

- Assistant mode selector in the chat title area or composer toolbar.
- Built-in assistant profiles:
  - `general`: balanced local ChatGPT-style assistant.
  - `novel`: fiction writing, long-form continuation, character consistency.
  - `analysis`: long conversation or document-style analysis.
  - `coding`: concise code assistant with file/path-aware phrasing.
  - `translation`: faithful translation and polishing.
- Writing action bar for novel workflows:
  - brainstorm premise;
  - create outline;
  - create character bible;
  - draft chapter;
  - continue scene;
  - rewrite selected text;
  - expand;
  - consistency check.
- Conversation analysis actions:
  - summarize current conversation;
  - extract decisions;
  - extract open questions;
  - extract timeline;
  - extract characters/worldbuilding notes when in novel mode.
- Automatic context compression:
  - estimate prompt pressure before generation;
  - summarize older turns when the request would exceed budget;
  - preserve the latest configurable number of turns verbatim;
  - store the generated summary as local conversation memory;
  - send memory as a system message in future requests;
  - never send assistant `reasoningContent` back into the model.
- Memory panel:
  - show compression status;
  - show remembered summary;
  - show number of compressed messages;
  - manual "压缩当前对话";
  - manual "清除压缩记忆".
- Tests for profiles, action prompt builders, compression logic, API non-stream completion, generation hook orchestration, and UI actions.
- Visual QA at `1000x760`, `1180x760`, and `1440x900`.

### Excluded From v2.1

- Cloud sync, accounts, or external APIs.
- Web browsing.
- Full document indexing or vector database RAG.
- Multi-model routing.
- Collaborative editing canvas.
- Model-specific tokenizer bindings. v2.1 keeps the current approximate token estimator.
- A separate novel project database. Novel data is stored inside ordinary conversations in v2.1.

```ts
export interface ChatCompletionMessage {
  content: string;
  reasoningContent: string;
}

interface CompleteChatOptions {
  host: string;
  port: number;
  messages: ChatRequestMessage[];
  sampling: SamplingParameters;
  signal?: AbortSignal;
}

export async function completeChatCompletion({
  host,
  port,
  messages,
  sampling,
  signal,
}: CompleteChatOptions): Promise<ChatCompletionMessage> {
  const response = await fetch(`http://${host}:${port}/v1/chat/completions`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(buildChatCompletionBody({ messages, sampling, stream: false })),
    signal,
  });

  if (!response.ok) {
    throw new Error(`聊天请求失败：HTTP ${response.status}`);
  }

  return parseCompletionMessage(await response.json());
}

export function parseCompletionMessage(payload: unknown): ChatCompletionMessage {
  const parsed = payload as {
    choices?: Array<{ message?: { content?: string; reasoning_content?: string } }>;
  };
  return {
    content: parsed.choices?.[0]?.message?.content ?? "",
    reasoningContent: parsed.choices?.[0]?.message?.reasoning_content ?? "",
  };
}
```

Create `src/lib/conversationCompression.ts`:

```ts
import type { ChatConversation, ChatMessage } from "../types/chat";
import type { ChatRequestMessage } from "../api/chat";

export interface CompressionSelection {
  compress: ChatMessage[];
  preserve: ChatMessage[];
}

export function selectMessagesForCompression(conversation: ChatConversation): CompressionSelection {
  const throughId = conversation.memory.compressedThroughMessageId;
  const startIndex = throughId
    ? conversation.messages.findIndex((message) => message.id === throughId) + 1
    : 0;
  const preserveCount = Math.max(2, conversation.compression.preserveRecentTurns * 2);
  const eligibleEnd = Math.max(startIndex, conversation.messages.length - preserveCount);
  const compress = conversation.messages
    .slice(startIndex, eligibleEnd)
    .filter((message) => message.status === "complete" && message.content.trim().length > 0);
  const preserve = conversation.messages.slice(eligibleEnd);
  return { compress, preserve };
}

export function buildCompressionPrompt(conversation: ChatConversation, messages: ChatMessage[]): string {
  const previous = conversation.memory.summary.trim() || "无";
  const transcript = messages
    .map((message) => `${roleLabel(message.role)}：${message.content}`)
    .join("\n\n");

  return [
    "请把以下长对话片段压缩为可继续用于后续对话的长期记忆。",
    "保留事实、决定、人物、设定、未解决问题、用户偏好、写作风格和后续任务。",
    "删除寒暄、重复内容和模型推理过程。",
    `已有长期记忆：\n${previous}`,
    `新增对话片段：\n${transcript}`,
    "输出中文 Markdown，分为：核心事实、用户偏好、人物/设定、未解决问题、下一步。",
  ].join("\n\n");
}

export function mergeConversationMemory(
  conversation: ChatConversation,
  summary: string,
  compressedThroughMessageId: string,
  compressedMessageCount: number,
): ChatConversation {
  return {
    ...conversation,
    memory: {
      summary: summary.trim(),
      updatedAt: new Date().toISOString(),
      compressedMessageCount: conversation.memory.compressedMessageCount + compressedMessageCount,
      compressedThroughMessageId,
    },
  };
}

export function buildCompressedRequestMessages(
  conversation: ChatConversation,
  preservedMessages: ChatMessage[],
): ChatRequestMessage[] {
  const messages: ChatRequestMessage[] = [];
  if (conversation.memory.summary.trim().length > 0) {
    messages.push({
      role: "system",
      content: `长期对话记忆：\n${conversation.memory.summary}`,
    });
  }
  for (const message of preservedMessages) {
    if (message.role === "system") continue;
    messages.push({
      role: message.role,
      content: message.content,
      attachments: message.role === "user" ? message.attachments : undefined,
    });
  }
  return messages;
}

function roleLabel(role: ChatMessage["role"]): string {
  if (role === "user") return "用户";
  if (role === "assistant") return "助手";
  return "系统";
}
```

Add helper:

```ts
async function compressConversationIfNeeded({
  conversation,
  contextSize,
  sampling,
  port,
  saveConversation,
}: {
  conversation: ChatConversation;
  contextSize: number;
  sampling: SamplingParameters;
  port: number;
  saveConversation: (conversation: ChatConversation) => Promise<void>;
}): Promise<ChatConversation> {
  if (!conversation.compression.enabled) return conversation;

  const requestMessages = buildRequestMessages(conversation, contextSize, sampling.maxTokens);
  const estimated = requestMessages.reduce((sum, message) => sum + message.content.length / 3, 0);
  if (estimated / contextSize < conversation.compression.triggerRatio) return conversation;

  const selection = selectMessagesForCompression(conversation);
  if (selection.compress.length === 0) return conversation;

  const lastCompressed = selection.compress[selection.compress.length - 1];
  const prompt = buildCompressionPrompt(conversation, selection.compress);
  const result = await completeChatCompletion({
    host: "127.0.0.1",
    port,
    messages: [{ role: "user", content: prompt }],
    sampling: {
      ...sampling,
      temperature: 0.2,
      maxTokens: conversation.compression.maxSummaryTokens,
    },
  });
  const compressed = mergeConversationMemory(
    conversation,
    result.content,
    lastCompressed.id,
    selection.compress.length,
  );
  await saveConversation(compressed);
  return compressed;
}
```

## Implementation Order

1. Task 1: Schema and migration.
2. Task 2: Assistant profiles and writing actions.
3. Task 3: Non-stream completion API.
4. Task 4: Compression engine.
5. Task 5: Automatic compression before generation.
6. Task 6: Assistant mode and memory UI.
7. Task 7: Writing and analysis action bar.
8. Task 8: Manual compression and analysis actions.
9. Task 9: Export and checklist updates.
10. Task 10: Full verification and visual QA.

This order keeps every step shippable. Compression logic is tested before it touches generation. UI appears only after data and generation behavior are stable.

## Risks And Mitigations

- **Compression quality depends on the local model.** Mitigation: preserve recent turns verbatim and show memory visibly so users can inspect or clear it.
- **Summaries may lose important details for novels.** Mitigation: novel mode compression prompt explicitly preserves characters, setting, voice, unresolved plot points, and continuity constraints.
- **Extra completion call adds latency.** Mitigation: only trigger compression above `triggerRatio`, allow manual compression, and skip when no eligible messages exist.
- **Small models may produce weak summaries.** Mitigation: keep summary editable in a later release; v2.1 at minimum supports clear and regenerate.
- **UI may become busy.** Mitigation: use compact controls near existing chat surfaces and keep the primary composer unchanged.

## Acceptance Criteria

- New and old conversations load without crashing.
- Users can switch assistant mode per conversation.
- Novel mode exposes writing actions and inserts actionable prompts.
- Analysis mode exposes conversation analysis actions.
- Long conversations automatically create local memory before generation when over budget.
- Requests include system profile prompt, long-term memory, and recent turns.
- Reasoning content is never included in compressed memory or future request content.
- Memory can be viewed, manually regenerated, and cleared.
- Markdown export includes long-term memory when present.
- All automated tests, production build, Rust checks, Tauri app bundle, real model smoke, and visual QA pass.
